# ADR-0002: Better Auth via official Drizzle adapter over D1

Status: Accepted (2026-08-14)

## Context

Requirements: email/password signup, verification, login, reset, session
management, org memberships/roles, CSRF, throttling — on Workers + D1,
current stable release only (no beta/RC).

Verified 2026-08-14 (better-auth.com docs via official repo): Better Auth
1.6.29 stable; two officially documented D1 routes:

1. Direct D1 (`database: env.DB`, built-in Kysely adapter) — supports
   programmatic `getMigrations`.
2. **`@better-auth/drizzle-adapter`** over `drizzle(env.DB)` with
   `provider: "sqlite"` — officially documented; auth schema generated by
   `npx @better-auth/cli generate` and migrated via drizzle-kit/wrangler
   (programmatic migrations unsupported on this route).

## Decision

Route 2: **Better Auth 1.6.x + official Drizzle adapter over D1.**

- The whole application schema lives in Drizzle; auth tables join it, so
  FKs from `organization_members` etc. to `users` stay in one schema, one
  migration chain (wrangler d1 migrations, using `migrations_pattern` if we
  adopt drizzle-kit's nested layout).
- Better Auth **organization plugin** (first-party, in core) models
  organizations/memberships/roles rather than a hand-rolled tenancy layer;
  app-level authorization still enforced in our repository layer.
- Workers specifics: `nodejs_compat` flag required; rate-limit storage set
  to `"database"` (in-memory default unusable on Workers) plus the native
  Workers rate-limit binding at the edge; CSRF stays at Better Auth's
  origin-validation defaults; secure cookie defaults kept.

## Consequences

- Auth schema changes arrive via CLI regeneration + a normal reviewed SQL
  migration — same safety procedure as any schema change.
- Sessions are DB-backed → each authed request reads D1; acceptable within
  the 25B row-read allowance; optional signed cookieCache if latency ever
  warrants (with its documented revocation caveat).
- Pinned to 1.6.x; Better Auth 1.7 (currently RC) adopted only after
  stable + upgrade-guide review (superseding ADR if the adapter path
  changes).

## Alternatives considered

- Direct-D1 Kysely route: simplest install, but splits the schema into two
  ORMs/migration styles and weakens FK integrity with app tables.
- Lucia/hand-rolled: Lucia deprecated as a library; hand-rolling auth is
  a security liability against the "cannot be wrong" bar.
- Clerk/Auth0/WorkOS: recurring per-MAU cost violates the cost ceiling and
  adds a subprocessor for no V1 gain.
